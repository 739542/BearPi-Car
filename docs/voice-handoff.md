# 语音遥控交接

## 接手时小车处于什么状态

车端基线为 car-stage1-v12。已验证板上启动、上电停车和热点就绪。手机能直接访问驾驶台，语音模块尚未加入固件。建议先做手持式语音遥控器：第二块 BearPi 负责听口令并加入 BearPi-Car 热点，车上继续运行 v12。这样可以在电机断电时完成大部分开发，也能减少电机噪声对麦克风的影响。若选择把模块装到车上，须另外实现本地语音与网页、串口之间的控制权协调。

## 第一步：只读命令 ID

实物板上印有 DF2301QG V1.0。断电，将通信拨杆拨向 I²C。白色 Gravity 四针座接数据线，右侧 SPK2 为扬声器接口。按两端丝印逐线核对，手持板接线如下。

| 模块端 | 照片线色 | BearPi-HM Nano 端 |
| --- | --- | --- |
| D/T | 蓝 | IO00，I²C SDA |
| C/R | 黄 | IO01，I²C SCL |
| GND | 黑 | GND |
| VCC | 红 | 3.3 V 供电，先核对电源余量 |

模块支持 3.3 至 5 V，接 Hi3861 时保持信号为 3.3 V。厂家给出 5 V 下峰值电流可达 370 mA。若播放提示音时板子复位，先检查供电余量；使用独立电源时须共地并核对 I²C 上拉电压。首次调试保持电机电池断开。

在 SDK 的 I²C 示例中配置 IO00、IO01 复用，从 100 kHz 起步。模块七位地址为 0x64，查清所用 SDK API 的地址参数约定后再决定是否左移。参照厂家库中 I²C 版 getCMDID 的寄存器访问次序移植读取函数。先打印时间、读操作返回值和命令 ID。读失败与成功读到 0 分开记录。唤醒模块，说出“前进”“后退”“停车”，核对是否分别返回 22、23、24。唤醒词和零值都应让车辆保持原状态。精确词表以手头模块的语言版本和实际日志为准。[厂家中文词表与接线说明](https://wiki.dfrobot.com.cn/SKU_SEN0539_Gravity_Voice_Recognition_I2C_UART) · [厂家驱动源码](https://github.com/DFRobot/DFRobot_DF2301Q)

## 第二步：单独调通无线接口

手持端的 Wi-Fi、语音映射和控制逻辑在 [voice_remote](../voice_remote/README.md)。先按该说明配置实际热点口令，断开电机电池，验证串口的 v12 状态和动作回执。

车端入口在 [wireless.c](../firmware/wireless.c)，已运行的请求样例可读 [board_transport.js](../web/board_transport.js)。手持板加入热点，由 DHCP 获取地址。目标为 192.168.4.1 的 TCP 80。先只请求 status，确认返回版本 v12。

每条请求使用 POST /control、请求头 X-Car-Control: 1，并带正确 Content-Length。正文是纯文本。下面各行代表独立请求的正文。示例中的 SESSION 需替换成 arm 返回的十进制 session 字符串。

~~~text
status
arm
drive SESSION 1 0 0
stop
~~~

status 返回 version 和 busy；arm 获取普通模式控制权。drive 的最后三项依次为递增序号、左轮输入、右轮输入，轮值区间 −30 到 30。stop 释放会话并要求停车。HTTP 409 表示车端拒绝请求，常见原因是控制权已被占用、会话过期、序号回退或输入越界。移动请求遇到拒绝就结束本次动作，等待下一次明确口令。手机正常驾驶期间忽略新的语音移动命令；“停车”可使用车端已有的 stop 请求中止运动。无线协议没有统一仲裁 USB 来源，联调时释放桌面控制台。

## 第三步：把一次口令变成一个有终点的动作

以下为首轮实现建议。表中数值是协议输入，需架空验证方向和起转能力后再落地校准。

| 口令 | ID | 左、右轮输入示例 | 结束条件 |
| --- | --- | --- | --- |
| 前进 | 22 | 15，15 | 最长 500 ms 后 stop |
| 后退 | 23 | −15，−15 | 同上 |
| 停车 | 24 | 立即发 stop | 取消当前动作与后续续发 |
| 左转 / 右转 | 建议各训练一个短口令，登记实测 ID | −15，15 / 15，−15 | 短时转向后停车 |
| 无结果、未知词、唤醒词 | 0 或其他非动作 ID | 无动作 | 继续监听 |

厂家内置 25 至 30 是带角度的转向词。首版建议使用自学习短词表达方向；若展示指定角度，要先标定。同一 ID 如果连续多次读到，只对新识别事件执行一次。可先观察模块是否在两次发声间返回 0，再决定用清零或重新触发作为去重依据。

当前手持端每次获取普通模式会话后发送一次 drive，目标动作时长约 300 ms，到期发 stop。I²C 监听独立运行，停车口令可以提前中止动作。断网或请求超时后，程序重新确认车端状态并等待新口令。

## 验收与交付

| 顺序 | 条件和操作 | 应保存的结果 |
| --- | --- | --- |
| 1 | 电机电池断开，分别说唤醒词、五个动作和无关词 | 词语与 ID 对照表；无关词没有运动请求 |
| 2 | 电机断开，手机占用会话时说前进，再说停车 | 启动被拒、停车被接受；无旧动作恢复 |
| 3 | 架空车轮，逐项执行五种口令 | 左右轮方向、单次最长运行时间、松开控制权后的停车记录 |
| 4 | 运动中断开手持板电源或热点连接，再恢复 | 车端超时停车；重连和手持板复位均保持静止 |
| 5 | 空地低速演示，安静环境与电机运行时各重复每词十次 | 每词成功次数、误触发次数、停车耗时和测试距离。报告观察值 |
| 6 | 完成语音测试后重新用手机驾驶并重演路线 | 手机仍能取得会话，双手控制和松手停车可用 |
